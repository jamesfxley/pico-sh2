# Standing deviations

Scope-wide suppressions require review under EN-00.5 and count against the
per-language ceiling under EN-00.6.

| Check | Scope | Rationale | Risk and mitigation | Approval | Review by |

| readability-magic-numbers | tests/ | EN-04.7, the exemption CXX-02.8 names explicitly. A literal size, offset or count in a test is the case under test, not a value shared with production code; hoisting it to a named constant moves the expected value away from the assertion that reads it. The library owns the overlay at `tests/.clang-tidy`. | A wrong expected value can agree with a defect in the implementation. Assertions compare behavior with the literal; review checks the expected value against the requirement or protocol, and other enabled checks remain active. | approved by the maintainer, 2026-10-29 | 2027-09-13 |
| readability-magic-numbers | src/ | CXX-02.8. This tree is a transcription of a published wire format. The seeded report-length table, the byte-order shifts and masks, the report field offsets and the FRS record IDs are the specification's numbers, each cited to the CEVA manual and section that defines it -- the report-length table names a subsection per entry, and the decoders name theirs at file scope; naming every one instead inserts an indirection between the code and the document it has to be checked against. | A genuinely wrong constant reads as plausible. Covered by the decoder round-trip and report-length tests, which fail on a wrong offset, and by the three libFuzzer targets, which exercise the framing and decode paths independently of any expected value written in a test. | approved by the maintainer, 2026-10-29 | 2027-09-13 |
| bugprone-unchecked-optional-access | tests/reports/ | EN-04.7. The guard is an `ASSERT_TRUE(x.has_value())`, which returns from the test on failure — control flow the check's dataflow analysis cannot see through a GoogleTest macro, so every finding here is a false positive. | A genuinely unguarded access would abort the test process instead of failing the assertion. The failure is still loud and still attributable to the test that caused it. | approved by the maintainer, 2026-10-29 | 2027-09-13 |
| cppcoreguidelines-virtual-class-destructor | tests/sh2/ | EN-04.7. Covered by the protected base destructor, which makes deletion through the interface a compile error. | approved by the maintainer, 2026-10-29 | 2027-09-13 |
| cppcoreguidelines-owning-memory | tests/sh2/ | EN-04.7, as for `cppcoreguidelines-no-malloc` in this same scope. | As for `cppcoreguidelines-no-malloc` in this same scope. | approved by the maintainer, 2026-10-29 | 2027-09-13 |
| cppcoreguidelines-no-malloc | tests/sh2/ | EN-04.7. | cppcoreguidelines-pro-bounds-pointer-arithmetic | tests/sh2/ | EN-04.7, as for `cppcoreguidelines-pro-bounds-pointer-arithmetic` in `tests/shtp/`. | As for `cppcoreguidelines-pro-bounds-pointer-arithmetic` in `tests/shtp/`. | approved by the maintainer, 2026-10-29 | 2027-09-13 |
| cppcoreguidelines-pro-bounds-pointer-arithmetic | tests/shtp/ | EN-04.7. A libFuzzer entry point is handed a raw pointer and a length by the framework, and constructing the `std::span` that makes the rest of the body bounds-safe is itself the pointer arithmetic the rule objects to. | The span could be built with a wrong extent and read out of bounds. Covered by the fuzzers themselves running under AddressSanitizer, which reports exactly that on the first input that triggers it. | approved by the maintainer, 2026-10-29 | 2027-09-13 |
| misc-include-cleaner | tests/docs/ | EN-03.5. Each harness here and the `.inc` its document generates are one translation unit split across two files by design: the harness supplies the includes and stubs, the `.inc` holds the example. The check reads each file's includes against that file's own uses, so every include a harness makes for its example reads as unused, and keeping them is the only way the example compiles. | An include a harness genuinely no longer needs stays. Bounded by the scope being harnesses only, each a few lines that `house_cxx_add_doc_examples` refuses unless it pairs with an example, and by every other check still applying to them. | approved by the maintainer, 2026-10-29 | 2027-09-13 |
| misc-use-internal-linkage | tests/docs/ | EN-03.5. The functions an example defines are a reader's code, with the external linkage a reader's code has; making them `static` or anonymous would show the reader a different program from the one they write, and an unused internal function is then a `-Wunused-function` error under the strict flags. | A function in a harness that should have been internal is not reported. Bounded by the scope holding only harnesses and the examples they include, none of which ships or is linked into anything. | approved by the maintainer, 2026-10-29 | 2027-09-13 |
| cppcoreguidelines-macro-usage | src/sh2/include/pico_sh2/sh2/session.hpp | EN-04.7. The region is a `NOLINTBEGIN`/`NOLINTEND` pair around that expansion. The region's two markers count as two suppressions (CXX-00.2). | A macro added inside the region is not reported. Bounded by the region being the counter list alone, the macro being undefined again after use, and every other check still applying. | approved by the maintainer, 2026-10-29 | 2027-09-13 |
| bugprone-macro-parentheses | src/sh2/include/pico_sh2/sh2/session.hpp | EN-04.7.
